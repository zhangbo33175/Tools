# 工程目录规范

本规范用于约束新增代码的落位。所有参与编译的自家代码统一收口在 `Assets/` 下，其中运行时三层的物理根为 `Assets/Honor/Runtime/`（`Models` / `Services` / `Controls`），避免工程再次退回“根目录堆文件、功能目录平铺”的状态。

## 1. 分层原则

- **入口只做装配**：`Assets/App/` 负责应用启动与主题装配，不承载业务逻辑。
- **视图只做编排**：`Assets/Views/` 负责窗口、事件接线与交互编排，不直接实现文件格式、地图协议或渲染算法。
- **控件只做呈现**：`Assets/Honor/Runtime/Controls/` 负责可复用控件、画布绘制与弹窗，不直接读写业务存档。
- **服务承载能力**：`Assets/Honor/Runtime/Services/` 按领域提供地图、发布、模板、PSD、动画、资源与基础设施能力。
- **模型只描述数据**：`Assets/Honor/Runtime/Models/` 存放 DTO、配置模型、几何与显示规则，不放业务流程。
- **第三方保持独立**：`Assets/ThirdParty/SpineRuntime/` 是外部运行时，不按本项目业务目录拆分。

## 2. 顶层职责

| 目录 | 职责 | 不应放置 |
| --- | --- | --- |
| `Assets/App/` | `Program`、`App.axaml`、应用入口、`app.manifest` | 窗口 partial、地图服务 |
| `Assets/Views/MainWindow/` | 主窗口壳、事件、面板接线、导入导出 | 通用控件、渲染算法 |
| `Assets/Honor/Runtime/` | `Models` / `Services` / `Controls` 三层运行时代码的物理目录容器 | 窗口、第三方运行时、资源素材 |
| `Assets/Honor/Runtime/Models/` | 数据模型与规则常量 | 文件 IO、UI 构造 |
| `Assets/Honor/Runtime/Services/` | 领域服务与基础设施 | 窗口、控件、XAML |
| `Assets/Honor/Runtime/Controls/` | 画布、面板、弹窗、主题、通用控件 | 存档协议、发布流程 |
| `Assets/ThirdParty/SpineRuntime/` | 第三方 Spine 运行时 | 项目业务代码 |
| `MapData/` | 运行期地图数据 | 源码 |
| `PSD/` | 本地 PSD 验证素材 | 源码 |
| `docs/` | 设计、诊断、测试数据与规范 | 参与编译的源码 |

## 3. 新增代码落位

### 3.1 UI

- 新的主窗口功能区：放 `Assets/Views/MainWindow/` 对应子目录。
  - 事件接线：`Events/`
  - 面板与浮窗布局：`Panels/`
  - 保存、导入、导出：`ImportExport/`
- 可复用基础控件：`Assets/Honor/Runtime/Controls/Common/`
- 自绘画布与网格：`Assets/Honor/Runtime/Controls/Canvas/`
- 编辑面板：`Assets/Honor/Runtime/Controls/Panels/`
- 独立弹窗：`Assets/Honor/Runtime/Controls/Windows/`
- 主题、画刷、字体与语义色：`Assets/Honor/Runtime/Controls/Theme/`

### 3.2 服务

- 路径、日志、文件 IO、JSON 选项、文件选择器：`Assets/Honor/Runtime/Services/Infrastructure/`
- 地图 JSON、图层、贴图、命中、遮挡、巡检：`Assets/Honor/Runtime/Services/Map/`
- Unity / Cocos / Lua 发布与发布设置：`Assets/Honor/Runtime/Services/Publish/`
- 模板仓库：`Assets/Honor/Runtime/Services/Templates/Store/`
- 配置表与 CSV / XLSM 读写：`Assets/Honor/Runtime/Services/Templates/ItemConfig/`
- PSD 解析、切片、合成、清单：`Assets/Honor/Runtime/Services/Psd/`
- Spine 与序列帧：`Assets/Honor/Runtime/Services/Animation/`
- 资源库、章节仓库、九宫格、轮廓识别：`Assets/Honor/Runtime/Services/Resources/`

### 3.3 模型

- 基础常量、设置、ID、资源分类与命名：`Assets/Honor/Runtime/Models/Core/`
- 地图、实例、交通、迷雾、菱形格：`Assets/Honor/Runtime/Models/Map/`
- 模板、显示名、九宫格、动画字段：`Assets/Honor/Runtime/Models/Template/`

## 4. 目录边界

以下相对名均指 `Assets/Honor/Runtime/` 下的同名目录。

- `Models/` 不引用 `Controls/`、`Views/`。
- `Services/` 不引用 `Controls/`、`Views/`；需要回调时由调用方注入委托。
- `Controls/` 可以引用 `Models/` 与 `Services/`，但不反向承载发布、存档等完整流程。
- `Assets/Views/` 只做编排，跨领域能力通过服务入口调用。
- 同一能力只能有一个公开入口；新增实现优先扩展现有入口，不另起平行工具类。

## 5. 命名与拆分

- 文件使用 PascalCase，文件名与主类型一致。
- partial 拆分使用 `类型.职责.cs`，例如 `ItemElementPanel.Persistence.cs`。
- 单文件只承担一个明确定义的职责；超过约 600 行优先按职责拆 partial。
- 现有文件保持 `MapEditorTool.Models / Services / Controls` 命名空间不变；搬目录不修改 namespace，新增文件沿用所在层既有 namespace。
- 新增目录必须同时更新 `README.md` 目录树与本规范。

## 6. 禁止回流

以下位置不允许再新增平铺源码：

- 工程根目录下的 `.cs`
- `Assets/Honor/Runtime/Models/` 根目录
- `Assets/Honor/Runtime/Services/` 根目录
- `Assets/Honor/Runtime/Controls/` 根目录
- `Assets/Views/MainWindow/` 根目录（仅允许窗口壳、核心状态与 `Properties`）

新增文件前先判断所属领域；无法归入现有目录时，先补规范，再建目录。

## 7. 变更验证

1. 移动或拆分前，把涉及文件备份到 `.tmp/<主题>_backup_<日期>/`。
2. 构建：`dotnet build MapEditorTool.csproj -v q --nologo`，要求 `0 警告 / 0 错误`。
3. 与服务相关的改动跑 `SharedHelpersSmoke`。
4. UI 相关改动真机加载 `docs/MapJson/Map_1m1.json`，确认 577 个物件正常。
5. 同步 `README.md` 目录树与正文路径；不留旧简写路径。
