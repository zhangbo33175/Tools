# 遮挡“缝隙”与 PSD 导入问题诊断 · 2026-11-22

## 0. 结论（先看这里）

这次截图里的“遮挡错误/缝隙”**不是**围栏贴图被切成多段，也**不是**同位置重复实例，而是：

> 这次截图里的“遮挡错误/缝隙”其实是**两个独立问题叠在一起**：
>
> 1. **硬切边**：PSD 背景组里的立体美术（`bg_rock_1_550_867` 这类灌木/岩石）在 JSON 里 `layerType=prop`，但旧代码先看 `bg_` 前缀，把它判成“地表带”，于是围栏（立体）后画，把灌木切出一条硬直边。
> 2. **18px 空缝**：围栏底边 2289、池塘顶边 2307，两者都在立体带，池塘脚底更低所以后画，但真实摆放留了 18px 空隙；围栏底下就露出一条绿色背景，看起来像“悬空/缝隙”。

已落地的修复：

- 分带优先级：`BandOverride` → 显式 `building / prop / character` → `foreground / bubble` → `background / road / greenery` → 名字兜底。`layerType=prop` 的 `bg_rock_1_550_867` 不再被 `bg_` 前缀拉回地表；`layerType=greenery` 的 `bg_grass_2` 仍在地表，不能按脚底 Y 盖到池塘上。
- 刷新阶段：`SceneDisplayAudit` 对背景/道路/绿化组里的树、灌木、围栏、建筑、人物做窄口提层，状态栏输出 `遮挡 自动提层 N`；保存后 `band` 写入 JSON。
- 接缝贴合：`OcclusionAdjustmentStrategy.SnapFlatSeams` 对“下方大平面件（池塘/水面/地毯，120–256px）+ 上方立体件”的 1–24px 窄缝，把下方件上移贴住上方脚底，状态栏输出 `接缝 贴合 N`；只动这类平面件，不碰小草丛和立体物之间的自然间距。
- 切片 `band` 元数据改为按真实 `layerKey` 计算，与地图实例分带一致。
- `bg_` 开头的合并层、`pond/water/road/rug` 等纯平面层仍留在地表，不会被误抬；显式 `prop` 的池塘按立体带走脚底 Y。

## 0.1 补充修复：绿化层 `bg_grass_2` 显示错误（2026-11-22 晚）

**现象**：选中 `bg_grass_2`（X=3976、Y=709、605×351、`layerType=greenery`、`hideWhenOffMap=true`）时，顶部出现一大块暗色矩形，压在池塘/草地区域上；取消选中后绿化大面积盖住本应更低的对象。

**根因（三个独立原因）**：

1. **分带把整层 `greenery` 当成立体物**：上一轮为了修正 `layerType=prop` 的 `bg_rock`/`prop_pond` 被 `bg_` 名字拉回地表，把 `greenery` 和 `building/prop/character` 一起写成了显式 `Standing`。`greenery` 是**绿化/地表组**，`bg_grass_2` 进入立体带后就按脚底 Y 后画，压住池塘、道具和人物。修复：显式 `greenery` 回到 `Ground`；只有 `ShouldPromoteToStanding` 窄口命中的独立树/灌木才提升。
2. **越界美术画到地图外**：`bg_grass_2` 在 `x=3976`、宽 `605`，右边界到 `4581`，超出 4096 约 485px。`MapCanvas.RenderCore` 之前没有按地图矩形裁剪，这块越界美术会画到深色画布底上；选中框又保留完整包围盒，视觉上就是一个“暗色大块”。修复：`groundItems / DrawTrafficGround / upperItems / DrawTrafficMarkers` 统一 `PushClip(0,0,config.Width,config.Height)`，只裁美术，不隐藏实例、不改坐标。
3. **选中绿化时 collision/shadow 调试填充把整块压灰**：PSD 批量导入给 `bg_grass_2` 带了 `collisionEnabled=true / shadowEnabled=true`，`DrawSelection` 会把 605×351 的碰撞区域和阴影区域同时铺上半透明红/紫填充，叠在绿色美术上就变成灰暗大块；用户截图里的“暗色矩形”主要来自这里，不是分带或贴图本身。修复：`item.LayerType == greenery` 时不再绘制 collision/shadow 填充，只保留选中外框与占格；其他层不受影响。

**选中态顺序修正**：`DrawSelectedOccupancy` 已移入地图裁剪层、贴在 ground/upper 贴图之前绘制，避免 Avalonia 把裁剪层整体合成到占格之上；选中绿化时不会再出现“占格盖住贴图”的变暗。

**实机验证（Map_1m1，577 实例）**：

- 只开「绿化」层选中 `bg_grass_2`（X=1587、Y=630、605×351）：绿化贴图保持原绿色，只有黄色选中框/占格，不再变灰暗。
- 第一次点「刷新层级」：`遮挡巡检：接缝贴合3；层号 42/577（地/立/叠 149/420/8）｜越界77(已裁)｜保存到JSON`。
- 第二次点：`遮挡巡检：无需修复｜层号已一致（地/立/叠 149/420/8）｜越界77(已裁)｜保存到JSON`，幂等。
- 分带核对：`bg_grass` 组 80 个实例全部回到地表；地表从 69 增到 149（69+80），立体从 500 降到 420，正好是这 80 个绿化层，没有误伤树/灌木的立体带。
- `BandCheck`：`grass: band=0 promote=False`；`pond(prop): band=1`，渲染顺序 `grass → fence/rock → pond`，池塘不会被草地盖住。

**仍存在、但不是本次分带错误**：`Map_1m1` 有 10 个绿化实例部分越界（8 个 `bg_grass_2` + 2 个 `bg_grass_1`），例如 `x=3976/width=605`、`x=-249`、`y=-125`。美术已裁到地图矩形内，选中框默认也裁到地图；需要检查完整边缘出血时，可在场景设置卡取消「裁剪越界」，此时美术和实例包围盒完整显示。是否把越界绿化整体移回/缩回地图，仍按美术摆放意图拍板。

**新增显示开关**：场景设置卡 `ClipOutsideMapToggle` → `MapCanvas.ShowClipOutsideMap`（默认 `true`）。勾选时 `DrawMapArt` 统一 `PushClip(0,0,Width,Height)`，`DrawSelection` 同样裁到地图；取消时两者都不裁，完整露出越界美术与选中框。开关只改绘制，不写实例坐标、尺寸、`bandOverride` 或 JSON；切换时状态栏会回显「裁剪越界：开启 / 关闭」。实机 16% 验证：开启时 4096 地图外没有越界图；关闭时顶部 `bg_grass_2`/边角地块完整露出，切回开启立即恢复干净边界。

## 0.3 红框层级：名称与画面不一致的植被（2026-11-23）

**现象**：红框里 `bg_grass_2`（`ce8143e2`，`greenery`，`sortOrder 19`）把右侧灌木切掉约 92px；该灌木实例 `fcd02ace` 名称是 `bg_rock_1_550_867`、`templateId=bg_rock_1`、`layerType=background`、`sortOrder 9`。同一模板的 `bg_rock_1.png` 是 126×41 扁平石板，而 `bg_rock_1_550_867.png` 是 118×123 绿色灌木。

**根因**：
- `LayerOrder.Compare` 先比遮挡带；`background` 属地表带、`greenery` 也属地表格，地表带内先比 `OrderBase`：background 0 < greenery 10；单改 `sortOrder`（9 → 19）无法跨层翻面。
- `LayerBands.IsStandingArt` 对 `bg_` 前缀直接返回 false，名称规则无法识别“石头名 / 灌木图”。
- 纯高宽比规则会误判 `bg_stop_1`（停车位标记，358×309、底边接触 97.5%）和 `bg_rock_2`（散落扁石，165×156、绿色 1.6%）。

**修复**：新增 `Assets/Honor/Runtime/Services/Resources/ArtSilhouetteInspector.cs`，读取 `AssetLibrary` 已缓存的位图，统计 BGRA 像素：
- 绿色占比 ≥22%（`bg_rock_1_550_867` 为 94.9%，`bg_rock_1` / `bg_stop_1` 为 0%，`bg_rock_2` 为 1.6%）；
- 有效内容高宽 ≥0.45、内容高 ≥40px；
- 底部 10% 高度接触率 ≤95%（灌木 53.7%，草地砖 / 停车位标记接近 100%）。
`OcclusionAdjustmentStrategy.Apply(config, visualResolver)` 在层组预筛后取位图，交 `LayerBands.ShouldPromoteToStanding(item, visuallyStanding)`；名称是 `bg_` 但视觉为植被、且 `IsFlatArt` 不为真时，写入 `BandOverride=Standing`、`BandOverrideAuto=true`。用户手改 `BandOverride` 的实例直接跳过。刷新巡检传入的 `hasRuntimeSprite` 为真时，视觉解析返回 null，避免 PSD 内存预览尚未落盘时拿磁盘旧图做误判；读图前先看 PNG IHDR，超过 200 万像素的整幅底图不进入解码/分析。

**验收**（headless，`Map_1m1`）：
- `SceneDisplayAudit.Apply` 输出 `bandPromoted=3`，只提升三个 `layerType=background` 的 `bg_rock_1_550_867`：`fcd02ace` / `956f40dc` / `886d24ce`；`bg_rock_1` 石板、`bg_rock_2`、`bg_stop_1` 均不提层。
- `bg_grass_1` / `bg_grass_2` 轮廓虽为绿色，但 `IsFlatArt` 命中草地名，`promote=False`；绿化层 80 个实例仍留在地表。
- 重排后 `fcd02ace`：`band=1`、`sort=49`、`base=40`、`slot=9`、`BandOverrideAuto=true`；与 `bg_grass_2` `ce8143e2` 比较返回 1（灌木后画、压在草皮上），与石板 `af4de2c1` 比较同样返回 1。

### 1.2 为什么会被判成地表

`Assets/Honor/Runtime/Services/Map/LayerBands.cs` 的**旧**判定顺序（问题版）：

```csharp
if (key is MapLayerKeys.Background or MapLayerKeys.Road)
{
    return Ground;   // ← 先于名字判定直接返回
}
...
if (ContainsWord(text, StandingWords)) return Standing;
if (text.StartsWith("bg_") || ContainsWord(text, GroundWords)) return Ground;
return Standing;
```

新顺序：

```csharp
if (key is "foreground" or "bubble") return Overlay;
if (key is "background" or "road") return Ground;
if (key is "building" or "prop" or "character" or "greenery") return Standing;
// 只有键缺失/未知才按名字：StandingWords → bg_/GroundWords → 默认 Standing
```

导入代码 `MainWindow.axaml.cs` 只把**整幅层**（`IsFullCanvasLayer`）压进底图；其余背景层会保留成独立实例，但 `LayerType` 仍是 `background`。于是同一个 `bg_rock_1_550_867`：

| 副本 | 图层键 | 名字 | 旧结果 | 新结果 |
| --- | --- | --- | --- | --- |
| `550,867` | `background` | `bg_rock_1_550_867` | 地表 0 | 地表 0（整幅背景组） |
| `912,2241` | `prop` | `bg_rock_1_550_867` | 地表 0（被 `bg_` 前缀误杀） | **立体 1** |
| 围栏 | `prop` | `prop_fence_2` | 立体 1 | 立体 1 |
| 池塘 | `prop` | `prop_pond_1` | 地表 0（被 `pond` 词误杀） | **立体 1** |

地表先画、立体后画，旧版围栏当然会切进灌木；新版 `bg_rock` 脚底 2364 比围栏 2289 更低，后画盖住立柱底部，硬切边消失。

### 1.3 之前“近重复实例”的判断要撤回

复核 `docs/MapJson/Map_1m1.json` 的五条 `prop_fence_2`：

| id | posX | posY | 宽高 |
| --- | --- | --- | --- |
| `560a6a78` | 1717 | 1776 | 345×93 |

虽然 `1717/1728` 水平只差 11px、`3037/3040` 只差 3px，但它们的 **Y 分别差 414px / 1104px**，不是同一位置的重复叠层；五条也不是“同一排围栏被切成五段”。因此**不要**按“近重复”去删实例，否则会误删正常布置。真正要修的是分带，不是去重。

### 1.4 边缘还有一层“淡边”问题（次要）

`MapData\Map\Chapter1\Level1\Props\prop_fence_2.png` 的外圈像素不是全透明：

- 首行/末行平均 alpha ≈ 33（约 13% 不透明），左右列有 25 个半透明像素；
- `PsdSliceBaker.ComputeTrim` 只把 `alpha == 0` 排除，`alpha = 33` 的边缘会保留；
- 在非整数缩放（截图为 113%）下，半透明边和透明区做双线性混合，会在轮廓外形成一条比背景更亮的“雾边”。

它通常表现为**沿着轮廓的一圈浅色描边**，而不是立柱中间的硬直缝。两者要分开修：硬切边是分带；雾边是 alpha/采样。

## 2. 本次已落地的代码

### 2.1 `LayerBands` 改为“显式图层键优先”

`Assets/Honor/Runtime/Services/Map/LayerBands.cs`：

- `Of(PlacedObject)`：`BandOverride` 最高；其次 `DisplayLayer`，否则 `LayerType`。
- `Of(key, name)`：`foreground/bubble → Overlay`；`background/road/greenery → Ground`；`building/prop/character → Standing`；
  只有键缺失/未知才看名字（先 `StandingWords`，再 `bg_`/`GroundWords`，否则 Standing）。
- `IsStandingArt(name)`：只认明确的立体词；`bg_` 前缀排除。
- `ShouldPromoteToStanding(item)`：条件限定为
  - `BandOverride` 仍是自动（-1）；
  - 图层键是 `background / road / greenery`；
  - 名字命中树、灌木、围栏、建筑、人物等立体词。

## 4. 让导入与遮挡更智能：建议的流水线

### 4.1 分带：多信号 + 置信度

按优先级打分，不再“图层键一票否决”：

| 信号 | 权重 | 说明 |
| --- | --- | --- |
| Unity `psd.json` 明确 `layerType` | 最高 | 有清单时以清单为准；但仍允许“非整幅背景 + 立体名”提升 |
| 实例 `BandOverride` | 最高 | 人工显式指定永远优先 |
| 整幅背景判定 | 高 | 只有真正铺满画布的层才并入底图 |
| 图层名立体词 / 平面词 | 中高 | 树、灌木、围栏、建筑、人物 → 立体；pond/water/road/rug → 地表 |
| 几何/alpha | 中 | 高宽比、底部不透明接触面积、有效高度；高而窄且底部接地 → 立体 |
| PSD 原始层序 | 低 | 只作同脚底 Y 的兜底，不能压过脚底 Y |

规则：

1. `BandOverride` / 显式 `foreground / bubble` → 叠加，永远最上。
2. 整幅 `background` → 并入底图，不生成实例。
3. 显式 `building / prop / character` → **立体**；即使名字以 `bg_` 开头或含 `pond`，也不再被名字拉回地表（本次修复）。
4. 显式 `greenery` → **地表**：`bg_grass_2` 这类大面积绿化层不能按脚底 Y 盖到池塘/道具上；绿化组里的独立树、灌木由 `ShouldPromoteToStanding` 窄口提升。
5. 显式 `background / road` → 地表；名字里的树/灌木词不改变它，避免整幅背景被拆成立体。
6. 只有图层键缺失/未知时才用名字：`StandingWords` → 立体，`bg_`/`GroundWords` → 地表，否则立体。
7. 任何自动判定都可被 `BandOverride` 覆盖；报告中显示“自动/手动”。

### 4.2 遮挡巡检：从“只报数”升级为“可解释 + 可回滚”

`SceneDisplayAudit` 建议增加四类检测（前两类已落地窄口版）：

1. **分带冲突**：地表带里出现“高而窄、底部接地”的美术；已实现 `BandPromoted`。
2. **平面件接缝**：池塘/水面/地毯这类大平面件与上方立体件只差 1–24px；已实现 `SeamSnapped`，自动上移贴合。
3. **同基线冲突**：两个立体实例 `Baseline` 差 ≤ 0.5，且包围盒重叠 > 20%；输出对象名、脚底 Y、重叠面积（未实现）。
4. **边缘透明度**：PNG 外圈存在 `0 < alpha < 32` 的像素，计入“雾边候选”（未实现）。

每条修复都记录：

```json
{ "rule": "promote-background-standing", "objectId": "...", "from": 0, "to": 1, "confidence": 0.92 }
```

提供“撤销本次自动修复”，只回滚 `BandOverride`，不碰用户手改项。

### 4.3 切片边缘：裁切 + bleed + 采样

1. **裁切阈值**：`alpha <= 8` 视为透明，去掉 1px 淡边；保留真正半透明的阴影/光效时，按图层名白名单跳过。
2. **1px 边缘 bleed**：导出时把最外圈不透明像素颜色向外扩 1px，alpha 仍为 0；避免双线性采样吸到背景色。
3. **预乘 alpha**：渲染端统一按预乘 alpha 合成，避免直通 alpha 在缩放下出现亮边。
4. **像素对齐**：非整数缩放时对 sprite 做 0.5px 对齐或使用最近邻；至少对 `prop` 类小图开启，避免栅格抖动。
5. **尺寸统一**：切片宽高必须与实例 `PixelWidth/PixelHeight` 一致；不一致时优先重切，不要用 `contain` 硬撑出透明边。

### 4.4 同名 / 重复 / 尺寸不一致

- **唯一键**：`安全名 + bbox(left,top,width,height)`，而不是只按名字。
- **像素哈希复用**：完全相同的像素只存一份 PNG；同名不同像素必须不同文件（已实现坐标后缀）。
- **近重复实例**：只在“同图哈希 + 同锚点 + 同 Y + 重叠 ≥ 95%”时提示合并；**不要**因 X 差 3px 就删，当前五条围栏 Y 不同，属于正常布置。
- **尺寸自动修复**：刷新发现 `PixelWidth/PixelHeight` 与 PNG 差 > 1 时：
  - 若 `image` 指向的图与 `slices.json` 的 bbox 匹配 → 自动改回正确尺寸；
  - 若同名文件尺寸不对 → 标记“需重导 PSD”，保存前阻断，避免带病落盘。
- **保存质量门**：`image` 空、缺图、尺寸不一致、`band` 与自动判定冲突，四类任一命中都给出明确阻断/确认提示。

### 4.5 PSD 导入的“预览 = 最终”原则

导入预览必须和最终地图使用**同一套排序函数**（当前 `MapCanvas` 已走 `LayerBands.Sort`），不能按 PSD 层序预览。验收标准：

- 预览中任取两个立体实例，脚底更低的后画；
- 地表带永远在立体带之前；
- 叠加带永远最后；
- 预览里的 `band` 与导出 JSON 的 `band` 一致。
